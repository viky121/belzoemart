## Design decisions (made by the planner)

- Export mapping is a pure exported function `toExportRows(product)` in `product.service.ts`, used by `ProductService.exportRows()`. Pure = unit-testable without Prisma; it sorts images by `position` itself so the join order is guaranteed regardless of the query.
- Export filter: `status in ['draft','published']` (the schema's only "deleted" state is `archived`; deletes are hard deletes). Products with zero variants produce no rows (a row needs a SKU). Variants ordered by `createdAt asc`, products by `createdAt desc` (matches `adminList`).
- CSV building/parsing moves to a new pure module `apps/web/src/lib/csv.ts` (testable by jest, whose `testMatch` is `**/*.test.ts`). The current bulk-page `parseCsv` splits on `\n` before handling quotes and would break exported multi-line descriptions (the editor says "one per line"), and it would read the BOM into the first header (`\uFEFFsku`) → "No valid rows". Both must be fixed for the round trip to work.
- Product CSV column list + `buildProductsCsv` + filename helper live in `apps/web/src/lib/product-csv.ts` (pure, no `admin-api` import so jest can load it). Next.js app-router `page.tsx` files may not export arbitrary names, so `COLUMNS` cannot be shared from the page.
- The fetch + Blob download is a small client component `apps/web/src/app/admin/catalogue/export-button.tsx` reused by the bulk page and the catalogue page header.
- Existing-SKU image rule: non-empty `imageUrls` → `deleteMany` + recreate in order inside the row transaction (duplicates within the cell dropped, first occurrence kept); empty/undefined → untouched. `title` (required column) and `categoryId` (required column, via `resolveCategory`) are now always updated for existing SKUs.
- Duplicate SKU in `VariantService.upsert` currently surfaces as a generic 500 (the global filter hides Prisma P2002). Add a pre-check that throws `ConflictException('SKU "X" is already used by another variant')` so the editor can show it.
- Editor variant save logic (change detection, payload that preserves `priceSlabsJson`/`attributesJson`/`weightGrams`/`imageUrl`, stock delta, validation) goes into a pure helper `apps/web/src/lib/variant-edit.ts` with jest tests; `product-editor.tsx` only wires UI + requests. One "Save details" button saves everything in order: product PATCH → images PUT → changed variants POST → stock adjusts → status PATCH.
- Current stock comes from `GET /admin/products/:id/variants` (`VariantService.listByProduct` already `include: { inventory: true }`), so no API change is needed for stock reads.
